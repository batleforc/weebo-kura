## Divergences

| # | Phase | RFC section | Divergence | Reason |
| --- | --- | --- | --- | --- |
| D1 | 1 | §4.4 (`/app/config.json`: issuer, client id) | It also carries `discovery`: `ui.oidc.discovery`, else `oidc.discovery`, else the issuer; the CSP's `connect-src` names that URL's origin | In Authentik's global issuer mode the issuer has no discovery document, and a browser may read only its own application's (CORS per application, found by RFC 0005's browser proof); `tests/heavy/console.sh` now checks it |
| D2 | 1 | §6.2 (`register_device` "returns" the session's web device) | `200` with the existing device, `201` for a new one | The client tells "registered" from "found" without comparing ids |
| D3 | 1 | §4.4 (`GET /me`: subject, tenant roles, platform admin) | Also `name` (`name`, else `preferred_username`) | The shell shows who is signed in; nothing beyond the caller's own token |
| D4 | 1 | §6.1 (the UI stage after the `weebo-containerfile` pattern) | Built from the committed `docs/api/openapi.json`, not from the built binary; the generated client is gitignored and regenerated by every `ui` script | `task openapi:check` already holds the spec equal to the handlers; the stage then does not wait for the Rust build (the template's TD-0003 §4) |
| D5 | 1 | §6.1 (proxy-cache's router guard, async-state, destructive-confirm and copy-button components; reka-ui) | A guard of the same rule (a route without `access` is refused) and an `AsyncState` written here; the revoke confirmation is an inline `alertdialog`; no reka-ui yet | Phase 1 needs one state component and one confirmation; the copy button and dialogs arrive with phase 2's Keys page |
| D6 | 1 | §4.5 (HTML mocks under `docs/RFC/assets/`, built in phase 1) | Not built | `batlehub-design` is still not installed here; the wireframes of §4.5 stand **Closed 2026-11-17**: `docs/RFC/assets/0003-console.html` (and `0005-reader.html`), built from the `batlehub-design` tokens and fonts, every state of §4.5. |
